## 事件级聚合变量：已存在，但以"广播"形式挂在阶段级行上

虽然数据集本身是阶段级，但**已经计算好了事件级的聚合结果变量**，并把同一个 Incident Reference 下所有阶段行都赋值为相同的事件级数值（即"广播"，broadcast）。实际检测到的新增聚合/派生列（不是命令原文假设的确切列名，如实记录实际列名）：

| 实际列名 | 含义 |
|---|---|
| `customers_v2_event_excl_reinterruptions` | 事件级客户数：排除标记为重复中断（`Re-interruption Stage` = Y 或旧式编码 `1`）的阶段后，对其余阶段的客户数求和 |
| `duration_A_customer_weighted_hours` | 事件级时长口径 A：客户数加权平均阶段时长（分母用全部阶段的原始客户数，**不排除重复中断阶段**——见 Step 1 的重要提示） |
| `duration_B_full_span_hours` | 事件级时长口径 B：全部阶段中最晚 End − 最早 Start（事件总跨度） |
| `Duration (hours)` | 兼容字段，直接等于 `duration_A_customer_weighted_hours`（脚本内注释明确标注为"Canonical compatibility field"） |
| `customer_minutes_lost_event` | 客户·分钟损失量（`duration_A`分子的60倍） |
| `event_customer_weight_denominator` | `duration_A` 计算时使用的客户数分母 |
| `all_stages_are_reinterruption` | 布尔标记：该事件的全部阶段是否都被标记为重复中断（即"边界情况"，客户数无法计算） |
| `stage_row_count` | 该事件对应的阶段行数 |
| `is_reinterruption_stage_v3` | 阶段级布尔标记：本阶段是否为重复中断阶段 |
| `stage_duration_hours` | 阶段级：该条 Restoration Stage 记录本身的起止时长 |
| `cause_code_norm` / `cause_group_official` | 标准化后的 Cause Code 及六分类分组（weather_natural / technical_asset / third_party / human_error / external_or_customer / non_fault_or_unknown） |

**结论对本命令后续步骤的影响**：因为数据是阶段级但已内置事件级聚合列，Step 1-2 的"事件级"审查（如 customers/duration 分布）需要先按 `Incident Reference` 去重（每个事件取一行）才能得到有意义的事件级统计，本报告后续步骤均已这样处理，并在每处明确标注是"阶段级"还是"事件级（去重后）"统计口径。
