## 一、Equation记法核对

### Equation 1（affected customers构造公式）

**核对文件**：`rebuild_v3_full_stage\scripts\build_stage_base_v3.py` 第94-134行。

**判定逻辑**（第106-107行）：
```python
reinterruption = df[REINTERRUPTION_COL].astype("string").str.strip().str.upper()
is_reinterruption = reinterruption.isin(REINTERRUPTION_TRUE_VALUES)  # {"Y", "1"}
```
判定字段是原始列**`Re-interruption Stage`**，取值"Y"或"1"（大小写统一后）判定为重复中断阶段。

**求和逻辑**（第115-116行）：
```python
eligible_customers = customers.mask(is_reinterruption)   # 重复中断阶段的客户数被置为NaN
customers_by_incident = eligible_customers.groupby(key, dropna=False).sum(min_count=1)
```
确认：**是"排除重复中断阶段后对客户数求和"，与论文公式 $C_i = \sum_{r \in \mathcal{R}_i \setminus \mathcal{I}_i} N_{i,r}$ 的求和逻辑一致。**

**⚠️ 与论文公式的具体差异（边界情况未被公式覆盖）**：`sum(min_count=1)`表示"如果参与求和的值全部是NaN，返回NaN而不是0"。这对应第117行`all_reinterruption`标记为True的**69个"全阶段皆重复中断"边界事件**（即$\mathcal{R}_i \setminus \mathcal{I}_i = \emptyset$的情况）——**代码的实际处理结果是`customers_v2 = NaN`（缺失，该事件被排除出后续建模样本），而不是数学上空集求和的常规约定值0**。论文公式如果照字面理解（空集求和=0），会让读者误以为这69个事件的$C_i=0$并保留在样本中，但实际实现是将其标记为缺失并排除。**建议在公式下方或脚注明确注明这一边界处理规则**，例如："For the 69 incidents where every stage is flagged as a re-interruption stage (i.e., $\mathcal{R}_i \setminus \mathcal{I}_i = \emptyset$), $C_i$ is treated as missing rather than zero, and these incidents are excluded from the estimation sample."

### Equation 2（restoration duration构造公式）

**核对文件**：同上，第98-100、123-124行。

```python
start = pd.to_datetime(df[START_COL], errors="coerce", utc=True)
end = pd.to_datetime(df[END_COL], errors="coerce", utc=True)
...
duration_b = (
    end.groupby(key, dropna=False).max() - start.groupby(key, dropna=False).min()
).dt.total_seconds() / 3600.0
```

确认：**"取全部阶段最晚End减最早Start"这一描述准确**，pandas的`.max()`/`.min()`默认`skipna=True`，即无法解析的时间戳（`errors="coerce"`产生的NaT）会被自动跳过，不需要额外处理逻辑，论文简化公式在这一点上没有遗漏。

**⚠️ 与Equation 1的一处不对称，公式本身未明确说明**：`duration_b`的计算直接用**全部阶段**（含重复中断阶段）的`start`/`end`列，**没有像`customers_v2`那样排除`is_reinterruption`标记的阶段**。也就是说，重复中断阶段虽然不计入客户数求和，但**其起止时间戳仍然参与duration_B的最晚/最早时间计算**。这是Equation 1和Equation 2之间一个真实存在、但两个公式并排放在一起时不会自然显现的方法论不对称，建议在方法论章节或附录B中明确说明，避免读者误以为两个变量对"重复中断阶段"的处理方式相同。

另外，`stage_duration = stage_duration.mask(stage_duration < 0)`（第101行）这一负值屏蔽只作用于`duration_A`的分子/分母计算（第120-122行），**不影响`duration_B`**——即使某一单独阶段的起止时间戳存在end早于start的记录错误，只要该阶段本身的start/end时间戳能被解析，仍会原样参与`duration_B`的max/min计算。这一点公式也未体现，建议一并注明。
