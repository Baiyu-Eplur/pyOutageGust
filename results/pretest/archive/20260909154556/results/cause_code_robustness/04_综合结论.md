# Step 4：综合结论——论文一正式采用哪个Cause Code范围作为主规格

## 明确建议：**weather_natural + technical_asset 作为主规格**（临界风速分析及模块D方差分解均适用）

理由如下，不含糊、不各打五十大板：

### 1. 理论契合度：weather_natural+technical_asset本就是更贴合研究目的的范围

论文一的研究目的是"纯粹的风对电力灾害的效应"，而全六组Cause Code里包含大量与风无关的类别——non_fault_or_unknown（本次样本占比高达38-39%，绝大部分是Cause Code 97 No Fault Found）、third_party、human_error、external_or_customer——这些类别的故障成因与阵风没有理论上的因果联系。weather_natural+technical_asset（technical_asset本身很大一部分可能是风致疲劳老化等间接风相关故障）在理论上就应该是更合理的分析总体，这不只是一次稳健性检验，而是**范围本身的选择就应该服务于研究目的**，这一点命令背景已经明确指出，本命令的实证结果进一步支持而非推翻这个理论判断。

### 2. 实证证据：暴露侧完全印证，恢复侧的减弱可以合理解释、不构成推翻理由

- **暴露侧（E0'）**：weather_natural+technical_asset子集（n=60,437）算出的临界风速点估计（10.69 m/s）与全六组（n=117,235，10.57 m/s）**高度一致**（相差仅1.1%），方向完全相同。子集下折间CV和Bootstrap CI置信度确有下降，但本命令判断**主要是样本量减半导致的统计功效下降**（呼应命令#10已确立的"样本量对系数稳定性有主导性影响"的结论），不是构成偏移导致的假信号——**暴露侧的临界风速估计在weather_natural+technical_asset子集里得到了独立验证，可以放心以这个理论上更合理的范围作为主规格**。
- **恢复侧（R0c'_B）**：weather_natural+technical_asset子集下效应本身趋近于零（β₁从0.0232降到0.0002），这**不是选错范围的证据，恰恰是范围选对之后揭示的更准确情况**——如果全六组的border-line显著结果本身就有相当一部分来自Cause Code构成偏移的复合假象（Step3已论证这一解释的权重更大），那么weather_natural+technical_asset子集给出的"效应证据不足"这个结论，比全六组给出的"看似显著"的结论**更接近真实情况**，不应该因为它"不好看"或"不显著"就放弃这个更严谨的范围、退回到统计上看起来更漂亮但可能掺杂假象的全六组结果。

### 3. 对下游分析（模块D方差分解等）的影响

**建议模块D及后续所有分析统一以weather_natural+technical_asset为主要分析总体**，与v6论文原始范围保持一致，便于新旧结果对照，也从根本上避免了third_party/non_fault_or_unknown等类别混入导致的解释力稀释和构成偏移风险。全六组的结果可以保留作为附录里的"大样本敏感性分析"，用于展示"扩大Cause Code范围后哪些结论保持稳定（暴露侧）、哪些不再稳定（恢复侧）"，这本身是一个有价值的方法论透明度展示，不需要因为选定主规格而删除。

### 4. 对临界风速具体数值报告的建议

- **暴露侧临界风速**：以weather_natural+technical_asset子集结果为主报告——约10.7 m/s（Delta CI [10.0, 11.4]，更保守的Bootstrap CI [9.2, 12.1]），并注明全六组独立复现了几乎相同的点估计（10.6 m/s）作为交叉验证证据。
- **恢复侧临界风速**：**不建议作为确立性发现重笔报告**。weather_natural+technical_asset子集下效应证据不足（β₁≈0，两种CI均大幅跨零），应改为探索性表述："在初步的大样本（全六组）分析中观察到一个约8.6 m/s的恢复侧临界风速，但该发现在限定为weather_natural+technical_asset的理论目标总体内未能得到统计上有说服力的支持，可能部分反映了Cause Code构成变化的复合效应而非纯粹的风力恢复关系；建议在天气API全量补齐、样本量进一步扩大后重新检验。"
