# Step 2：完整输入-脚本-输出链路图

## 链路总览（有向图，文字描述）

```
[原始数据] data/ukpn-iis.csv (237,901 行, 含多条 Restoration Stage/incident)
        │
        ▼  filter.py：Cause Code 分组 + 保留 weather_natural/technical_asset + 按 Incident Reference 去重（只留最早一条）
[data/new/unplanned_incidents_clean_2.csv]  (66,080 行, 23 列)
        │
        ▼  main1.py：解析坐标/时间 + 调用 Open-Meteo 历史天气 API + dropna(clean_start/lat/lon)
[data/new/ukpn_master_weather_matrix.csv]  (62,928 行, 301 列)  ← 行数在此处从 66,080 降到 62,928
        │
        ▼  match_lad.py：geopandas 点落区空间连接 (LAD_DEC_2021_UK_BGC.shp)
[data/new/ukpn_master_weather_matrix_with_lad.csv]  (62,928 行, 310 列)
        │
        ▼  poppulation_merge.py：宽表→长表 + 按 LAD21CD × year 合并 ONS 人口 (myebtablesuk20112024.xlsx, sheet MYEB3)
[data/new/ukpn_master_weather_matrix_with_lad_pop.csv]  (62,928 行, 323 列)
   (副产物: data/population_lad_long.csv)
        │
        ▼  Buckinghamshire_combination.py：合并 IMD 剥夺/城乡指标 (localincomedeprivationdata.xlsx) + Buckinghamshire 新旧LAD人口加权 crosswalk

        │
        ▼  GVA_merge_with_crosswalk.py：合并 GVA/行业结构 (依赖 GVA_new.py 预先生成的 data/gva_industry_2016.csv) + 同样的 Buckinghamshire crosswalk（人口加权求和 + 重算 per-head 和 share）
[data/new/ukpn_master_final.csv]  (62,928 行, 358 列)
        │
        ▼  LAD_GeoMerge.py：合并 LAD 地理/DNO 特征表 (依赖 LAD_AreaSummary.py → LAD_urban_Summary.py → LAD_DNO.py 三步生成的 LAD_full_dataset_with_dno.csv)
[data/new/ukpn_master_with_lad_features.csv]  (62,928 行, 369 列)
        │
        ▼  data_arrange.py：计算 Duration (hours)、Daytime Indicator、Hour、Month、Weekday

```

`LAD_GeoMerge.py` 的输入 `LAD_full_dataset_with_dno.csv` 本身是一条独立的三步子链路（不改变主事件表行数，是并行准备的 LAD 级参考表）：

```
[LAD shapefile] LAD_DEC_2021_UK_BGC.shp
        │  LAD_AreaSummary.py：计算每个 LAD 面积
[LAD_area.csv]
        │  LAD_urban_Summary.py：与 BUA 2022 GB 边界求交集，计算建成区比例
[LAD_area_with_bua_gb.csv]
        │  LAD_DNO.py：与 DNO 牌照区边界求交集，取最大重叠 DNO
[LAD_full_dataset_with_dno.csv]
```

`GVA_merge_with_crosswalk.py` 的输入 `gva_industry_2016.csv` 同样是独立预先生成的（`GVA_new.py`，从 `regionalgvabbylainuk.xlsx` 提取 2016 年 GVA 数据，非事件级，不改变行数）。

## 追溯到最原始文件的确认

链路已完整追溯到以下几类"非任何脚本产出"的原始数据文件：

- `data/ukpn-iis.csv`——UK Power Networks 停电事件原始记录（Ofgem IIS 申报数据，已去除官方 CI/CML 计算结果，只保留源数据；参见 `project_memory/data_source_inventory.md` 第 1 节）。
- Open-Meteo 历史天气 API（无本地原始文件，通过 API 实时调用 + 本地缓存 `.weather_cache_master.sqlite`）。
- `data/Local_Authority_Districts_December_2021_UK_BGC_2022/LAD_DEC_2021_UK_BGC.shp`——ONS LAD 边界（2021年12月版）。
- `data/myebtablesuk20112024.xlsx`——ONS 人口估计详细时间序列。
- `data/localincomedeprivationdata.xlsx`——英国 2019 年剥夺指数（IMD）相关数据。
- `data/regionalgvabbylainuk.xlsx`——ONS 地区 GVA 数据。
- `data/BUA_2022_GB_-3259870081615132876/BUA_2022_GB.shp`——ONS/OS 建成区（BUA）2022 边界。
- `data/dno_license_areas_20200506/DNO_License_Areas_20200506.shp`——NESO DNO 牌照区边界。

以上均已在 `project_memory/data_source_inventory.md` 中标注了具体来源网址（GOV.UK / ONS / data.gov.uk / NESO / Open-Meteo），本命令核实这些引用与脚本代码里实际读取的文件名/sheet 名一致，未发现矛盾。
