# 旧研究统一入口使用说明

本轮先完成旧项目收束。导师 `Comments` 代码尚未迁入；现有统计模型、筛样规则与图形风格沿用旧实现。

## 1. 日常只改 main.py

在项目根目录 `main.py` 顶部设置参数，再运行 `python main.py`。不需要创建 config 文件。

| 参数 | 用途 |
|---|---|
| `RUN_PRETEST` | 旧研究总开关，1 开，0 关 |
| `RUN_PURPOSE` | 本次运行目的，不能为空；例如“仅重画 Figure 4，检查旧曲线” |
| `PRETEST_STEPS` | 每个独立步骤的 0/1 开关，按字典中的顺序执行 |
| `DRY_RUN` | 1 只列出启用步骤并保存计划；0 实际执行 |
| `CONTINUE_ON_ERROR` | 0 遇错停止；1 记录失败并继续其他已开启步骤 |
| `PYTHON_EXECUTABLE` | None 使用当前 Python，也可指定解释器绝对路径 |

推荐使用既有 conda 环境 `pyoutagegust`。本机验证解释器为 `C:/Users/haoya/.conda/envs/pyoutagegust/python.exe`。
若 IDE 已选择这个环境，直接运行 main.py 即可。默认所有具体步骤为 0。

只重新绘制 Figure 4：填写目的，把 `final_combined_analysis/figure4_dose_response` 改为 1，其余保持 0。
重建最终样本并回归：同时开启 `model_review_package_20260907/materialize_final_data`、`review_package/run_main_regression`。
只复查回归：仅开启后者，使用已有样本。

开关控制独立脚本是否执行，不会关闭该脚本内部必要的函数调用。例如部分绘图脚本本来就会重建样本或拟合模型；开关不是把它们自动改为纯绘图。纯读取已保存曲线的 Figure 4 已单独验证。

## 2. 输出与运行记录

统一位于 `results/pretest/`，时间格式为 14 位 `YYYYMMDDHHMMSS`（年月日时分秒）。

| 路径 | 内容 |
|---|---|
| `archive/20260909154556/` | 本次迁移前的 721 份输出，原文件内容不变 |
| `figures/<时间>/<步骤序号>/` | 绘图步骤的结果 |
| `models/<时间>/<步骤序号>/` | 拟合及回归步骤结果 |
| `data/<时间>/<步骤序号>/` | 数据处理和样本生成结果 |
| `analysis/<时间>/<步骤序号>/` | 其他分析、稳健性与检验流程结果 |
| `checks/<时间>/<步骤序号>/` | 审计、输入检查、诊断结果 |
| `runs/<时间>/run.json` | 运行目的、开关、解释器、源码校验、逐步状态及输出清单 |
| `runs/<时间>/README.md` | 本次运行的简短说明和步骤结果目录 |
| `runs/<时间>/<步骤序号>/console.log` | 该步骤的 stdout/stderr，错误堆栈也在这里 |
| `runs/<时间>/<步骤序号>/inputs.jsonl` | 显式读取的输入位置、文件大小、修改时间和旧项目依赖标记 |
| `latest.json` | 每个逻辑结果文件当前可复用的成功版本位置；由程序维护，不是配置文件 |

分类按步骤功能确定；同一步产生的表格、图、JSON 保留原来的内部层级以便对应。步骤序号防止同一运行中的不同版本或导入副作用覆盖彼此。例如已验证的图片位于：

`results/pretest/figures/20260909154622/001/final_combined_analysis/figures/Figure_4_dose_response.png`

即使一个步骤失败，已有日志和部分产物也保留；失败产物不会进入 `latest.json`。若选择失败后继续，后续步骤可能使用此前成功的前置结果，其真实读取位置会记入 `inputs.jsonl`。全部步骤关闭和预演也会留下一条运行记录。

每次运行获得独立目录；同一秒内重复启动会顺延一个可用的秒级编号，实际开始/结束时间另行记录。运行锁防止两个进程同时更新结果索引。若进程被系统强杀，先确认没有运行进程，再移除 `results/pretest/.run.lock`；正常失败和 Ctrl+C 会自动释放。

## 3. 关闭前置步骤时如何读取结果

显式读取按以下顺序处理：本步骤已经产生的文件 → 最近成功结果索引（初始索引指向迁移归档）→ 对应的静态输入。
因此无需为了重新画图而重新运行上游拟合，也不会把新文件写回历史目录。
必需的前置结果缺失时，会报出逻辑文件名并提示开启生成步骤。

原始数据优先读取 `data/external` 中已有的迁移快照。少数早期脚本所需的输入尚无本地副本，保留原有 `D:/Pyprogramme/STST2603` 只读依赖；清单见 `migration_history/pretest_input_dependencies_20260909.json`。这一步没有声称所有历史研究包已完全脱离旧项目。
V2 天气下载可能耗时且需要网络，仅在明确开启 `pipeline_v2/main1_v2` 时执行；缓存读取可复用既有文件，新增缓存写入本次结果目录。

## 4. 接入范围与验证边界

`scripts` 共 120 个 Python 文件：116 个可独立运行的功能和 4 个公共模块；另加 review_package 回归，共 117 个开关。
公共模块为 `appendix_h_common.py`、`clean_sample_builder.py`、`r02_events.py` 和 `figure_style.py`，通过各步骤的导入调用，不提供空操作开关。
R02 输入消费模块用只读适配器调用并输出输入检查摘要。新增脚本时需要把开关加入 main.py，入口会检查清单完整性。

`paper_revision_work_v2` 与 `test` 中原有独立/冻结研究包仍是历史研究资料，保留代码、数据、文档及原入口，不在本轮迁入范围；Comments 也未修改。本轮接入的是用户指定的 scripts 全部旧功能和对应主回归。
部分 V2 脚本历史上就读取不同阶段/不同文件名，登记开关不代表已修正为一条完整新数据生产链；本轮不悄然更改这些统计及数据版本关系。

已验证：主入口、所有活动脚本语法、前置结果复用、失败隔离、写入边界、秒级目录冲突（11 项框架测试）；并真实重跑纯绘图、最终样本及主回归。
两份样本、四份系数表和回归摘要共 7 个文件与旧结果 SHA256 完全相同。未批量重跑全部 bootstrap、天气下载及所有历史分析。
V2 的 LAD 面积输出和全量事件聚合也已通过执行验证（237901 阶段 → 135025 事件）；R02 只读输入检查及既有 15 项事件/天气规则测试通过。V2 首次运行因新目录缺少父路径失败，已修正并在运行 `20260909155522` 复验成功；失败记录保留用于追溯。

开发更新逐步见根目录 `LOG.md`；归档迁移逐文件记录见 `migration_history/pretest_archive_20260909.json`；数值复现见 `migration_history/pretest_numerical_verification_20260909.json`。
